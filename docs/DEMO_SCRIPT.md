# Demo script

Target duration: 3 to 5 minutes. Record the running desktop browser application and actual operations. Use fictional demonstration data. Follow the final interface labels if they differ from this outline.

1. Introduce the problem: after an event, recoverable material remains and teams need to know where it actually went. Explain that a scan is not recovery.
2. Open the demo and show the selected fictional event and persisted totals. Switch to the field worker role. Capture cardboard in a zone, confirm manual classification, enter an estimated weight and photo evidence, then save.
3. Show the compatible batch in the coordinator view. Explain the material and zone grouping reason. Retry the same operation ID through the test or API demonstration and show that the count does not increase.
4. Assign a compatible fictional partner. Attempt an incompatible assignment and show the rejection. Switch to worker and record collection.
5. Switch to partner and record a measured receipt with less accepted weight than collected weight. Enter a rejected quantity, rejection reason, and evidence. Point out the discrepancy and the difference between collected and accepted quantities.
6. Switch to coordinator, review the receipt, and verify the accepted portion under the demo policy. Show the passport, machine-readable download and public verification key. Change a signed quantity in a copied passport and show failed verification.
7. Open reports and export CSV/PDF. Compare accepted recovery and rejection totals with the receipt. Carbon estimates remain unavailable rather than use invented factors.
8. Demonstrate offline capture in a second browser session: disconnect, save, reload, show the pending item, reconnect and retry. Show the coordinator's persisted change. Only describe this as tested if the actual browser run succeeds.
9. Close with the boundaries: manual classification, connected service verification pending where credentials are absent, and signatures attest records rather than physical truth.

Do not splice prerecorded state changes into a claim of live synchronization. Show a real forbidden action response in the API or automated test evidence. Do not include credentials or private operational contacts in the recording.
